# Analyze - `instructions-session-review::file-content::default`

## Role

A human-facing presentation schema for enriching Pi file activity with file purpose and repository instructions.

## Task

This Analyzer defines the storage contract for results produced by a deterministic program. The program reads `code-intent` analysis, selects declarative rules with the `agents-md` topic, matches those rules to repository-relative file paths, formats compact Markdown, and writes the results with `gsc app analysis set`.

The Analyzer does not require an LLM to populate its fields. When metadata is supplied directly by the deterministic program:

1. Validate every field against the schema below.
2. Preserve `read_items`, `edit_items`, and `write_items` exactly as supplied.
3. Store the validated fields as `extracted_metadata`.
4. Do not infer, expand, rewrite, or supplement missing values.

If deterministic metadata is not supplied, use empty strings and arrays. Do not recreate file purpose or repository rules from the target file.

## Review Item Contract

`read_items`, `edit_items`, and `write_items` are arrays of classified review-item objects. Every item must contain exactly these presentation fields:

* `group` — a short section label such as `AGENTS.md reminders` or `File context`.
* `key` — a stable machine identifier used to merge the same item across files and operations.
* `title` — a short human-facing statement such as `Run the repository check after code changes`.
* `markdown` — the complete detail shown when a reviewer opens an occurrence.

Contract rules:

* Use standard Markdown only in `markdown`. Do not include raw HTML.
* Keep `group`, `key`, and `title` useful without reading the target file path.
* Use the same rule-derived `key` across files and operations so its occurrences can be grouped.
* `read_items` describes the file context introduced by a read.
* `edit_items` contains file context and one independent item for every matching edit reminder.
* `write_items` contains file context and one independent item for every matching write reminder.
* Include only declarative rules whose topic is `agents-md` and whose file selectors match the target path.
* Omit items whose source metadata is unavailable. Use an empty array when no items apply.
* Do not infer why the agent read or edited the file.
* Do not claim that the agent saw, remembered, or followed a reminder.

## Context

The metadata is a deterministic, human-ready projection of AI-generated file purpose and repository-authored rules. It demonstrates how GitSense Chat can combine AI and deterministic sources without another model call.

## Input

Process only files supplied in the `## FILE CONTENT` message. Files supplied in `## REFERENCE FILE CONTENT` are context only and must not produce records.

## Processing Steps

1. Initialize `global_file_counter = 0`.
2. For each target file:
   a. Increment `global_file_counter`.
   b. If the target does not exist, print only: `File {{ANALYZER: global_file_counter}}: {{ANALYZER: Full File Path}} - File not found. Overview and metadata cannot be generated.`
   c. Otherwise print `File {{ANALYZER: global_file_counter}}: {{ANALYZER: Full File Path}}`, then emit the Markdown and JSON blocks below.

```markdown
# GitSense Chat Analysis

* **Chat ID:** {{ANALYZER: Chat ID from file context}}
* **Producer:** Deterministic external program

## Read Items

## Edit Items

### Custom Metadata Definitions

* `file_path` (string): Repository-relative target file path.
* `file_name` (string): Target filename including extension.
* `file_extension` (string): Extension without a leading dot, or an empty string when unavailable.
* `chat_id` (integer): Chat identifier from file context.
* `read_items` (array of objects): Classified items surfaced for a file-read event.
* `edit_items` (array of objects): Classified items surfaced for a file-edit event.
* `write_items` (array of objects): Classified items surfaced for a file-write event.
* `source_analyzers` (array of strings): Source IDs that contributed to any review-item array.
* `source_fingerprint` (string): SHA-256 of the canonical source metadata used by the deterministic producer.

### JSON Generation and Validation Rules

The `extracted_metadata` object must be valid JSON. Do not include comments. Preserve newlines in Markdown as escaped `\n` characters. Use empty strings or arrays when values are unavailable. Objects nested inside `read_items`, `edit_items`, and `write_items` are required by this deterministic contract; do not create nested objects in any other field.
```
