# Analyze - `agents-md::file-content::default`

## Role

This Analyzer defines a deterministic metadata contract for repository
instructions. It receives file records produced by
`.gitsense/bin/build-agents-md` and preserves the `catch` items exactly as
supplied. It must not infer whether an agent saw, understood, or followed an
instruction.

The analyzer is a review aid for `AGENTS.md` and compatible repository
instruction rules. It makes those instructions file-aware; it does not replace
the instruction file.

## Review Item Contract

`catch` is an operation-neutral array of objects. Each item contains:

* `group` — `AGENTS.md catches`.
* `key` — a stable identifier such as `catch:<rule-id>`.
* `title` — a concise statement of the applicable instruction.
* `topics` — an optional array of compact topic labels.
* `keywords` — an optional array of compact keywords.
* `short_markdown` — an authored compact review prompt.
* `long_markdown` — the complete instruction and review context.
* `markdown` — a compatibility alias containing the same value as `long_markdown`.

Use standard Markdown only. Preserve all supplied fields and Markdown. Do not
mechanically truncate `long_markdown` to create `short_markdown`.

## Deterministic Processing

For each target file:

1. Preserve the supplied repository-relative `file_path`.
2. Preserve the supplied `catch` array exactly, or use an empty array.
3. Preserve `source_analyzers` and `source_fingerprint` exactly.
4. Do not create catches from command-only rules because they have no file
   attachment in this contract.
5. Do not add a catch merely because a file was read, edited, or written; a
   matching file-scoped rule is required.

The resulting metadata is conceptually:

```json
{
  "description": "Deterministic AGENTS.md review catches matched to a file.",
  "label": "AGENTS.md Catches",
  "version": "1.0.0",
  "tags": ["agents-md", "deterministic", "session-review"],
  "requires_reference_files": false,
  "extracted_metadata": {
    "file_path": "{{ANALYZER: Repository-relative file path}}",
    "catch": {{ANALYZER: JSON array of supplied catch items}},
    "source_analyzers": {{ANALYZER: JSON array of source IDs}},
    "source_fingerprint": "{{ANALYZER: SHA-256 supplied by the deterministic producer}}"
  }
}
```

The `catch` array is allowed to be empty when no file-scoped instruction
matches. Missing source metadata must not be reconstructed from the target
file.

## Important Limitation

A matching catch identifies repository context that should be checked. It does
not establish that the agent missed the instruction or that the resulting code
is incorrect. The reviewer must compare the catch with the session activity and
the code.
